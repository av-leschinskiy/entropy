# Адаптивный символьный режим Typing Trainer

## Цель

Добавить в Typing Trainer простой режим тренировки символов текущей раскладки.
Он должен сначала равномерно показывать весь доступный печатаемый набор, а затем
чаще включать символы, в которых пользователь ошибается. Цель — помогать
практиковать реальные слои клавиатуры, включая символы с `Shift`, без ручной
настройки уроков.

## Границы первого релиза

В релиз входят:

- новый режим `Symbols` рядом с существующими `Time` и `Words`;
- извлечение печатаемых символов из всех доступных слоёв выбранной клавиатуры;
- учёт букв, цифр, пунктуации и вариантов с `Shift`;
- единая локальная статистика попыток и ошибок для каждого Unicode-символа;
- генерация упражнений с адаптивным взвешиванием слабых символов;
- совместимое чтение уже сохранённых настроек и истории;
- тесты модели данных и генератора.

В первый релиз не входят ручные наборы, уроки по пальцам/группам клавиш,
отдельные профили по устройствам и раскладкам, графики статистики или изменения
прошивки.

## Пользовательский сценарий

1. Пользователь подключает клавиатуру и открывает Typing Trainer.
2. В селекторе режима выбирает `Symbols`, затем длину упражнения: 25, 50 или
   100 символов.
3. Entropy получает отображаемые символы из всех доступных слоёв keymap,
   включая модифицированные `Shift` варианты, и исключает дубликаты.
4. Тренажёр показывает последовательность символов. В новом профиле все
   символы имеют одинаковую вероятность.
5. При несовпадении ввода с ожидаемым символом увеличивается счётчик ошибок
   **ожидаемого** символа. `Backspace` исправляет отображаемый прогресс, но не
   отменяет уже зафиксированную ошибку.
6. В следующих упражнениях проблемные символы попадаются чаще, однако у
   каждого доступного символа сохраняется ненулевая базовая вероятность.

Если клавиатура отключена либо извлечь печатаемые символы не удалось, режим
нельзя начать: интерфейс показывает объяснение вместо пустого упражнения.

## Модель данных и сохранение

`TypingTrainerMode` получает вариант `Symbols`. Настройки дополняются длиной
символьного упражнения; старые режимы и их поля сохраняются без изменений.

В `AppSettings` добавляется сериализуемая таблица статистики вида
`BTreeMap<char, TypingTrainerCharacterStats>`, где запись содержит:

- `attempts` — число предъявлений символа;
- `errors` — число ошибочных вводов при ожидании этого символа.

Статистика глобальна для приложения: не разделяется по устройству, языку или
раскладке. При другой клавиатуре используются только записи символов, которые
пересекаются с её доступным набором. Поля помечаются `#[serde(default)]`, чтобы
существующий файл настроек открывался с пустой статистикой.

История запусков получает `Symbols` как значение режима и те же агрегаты,
которые уже хранит (`errors`, `typed_chars`, точность и время). Отдельный экран
статистики не добавляется.

## Получение набора символов

Новый чистый слой модели строит `BTreeSet<char>` из загруженного keymap:

- перебирает все доступные слои и реальные назначения клавиш;
- отбрасывает прозрачные, управляющие и не генерирующие текст keycode;
- преобразует поддерживаемые базовые keycode и их `Shift`-варианты в символы;
- объединяет результат и сортирует его для воспроизводимости.

Набор формируется только по текущему, уже прочитанному Entropy keymap; запросов
к прошивке на каждое упражнение не требуется. Невозможные для отображения или
неоднозначные keycode пропускаются. В первом релизе не синтезируются символы,
которые требуют `AltGr`, Compose, макроса или нескольких отдельных клавиш.

## Генерация упражнений

Генератор принимает доступный отсортированный набор, статистику и seed. Для
каждого символа вычисляется вес:

```
weight = 1 + errors / max(attempts, 1)
```

Базовая единица гарантирует покрытие всего набора; ошибка увеличивает вес не
более чем вдвое. Генератор выбирает символы пропорционально весам и для набора
из двух и более символов гарантирует, что упражнение не состоит из повторения
одного символа. После каждого предъявления увеличивается `attempts`; при
неверном вводе увеличивается `errors` ожидаемого символа.

Это намеренно простой алгоритм: он прозрачен, не требует новых зависимостей и
может быть заменён позднее, не меняя формат статистики.

## Интерфейс

В существующем выпадающем списке режимов появляется локализованное значение
`Symbols`. Для него показывается отдельный селектор длины `25 / 50 / 100`.
Селекторы языка, пунктуации и цифр скрываются: их заменяет набор фактической
раскладки. Экран результата и история используют существующие WPM, точность,
ошибки, число символов и время.

## Ошибки и крайние случаи

- Пустой набор символов не создаёт упражнение и не изменяет статистику.
- Один доступный символ допустим: упражнение содержит его повторения.
- Дубликаты между слоями не дают дополнительного веса.
- Устаревшие сохранённые настройки нормализуются к безопасным значениям.
- `Retry` повторяет тот же target-текст, но не откатывает уже сохранённую
  статистику предыдущего законченного запуска.

## Проверка

Автоматические тесты должны доказать:

1. извлечение объединяет слои, включает Shift-варианты и отбрасывает не-текст;
2. пустой и односимвольный наборы безопасны;
3. новая статистика serde-совместима со старыми настройками;
4. без ошибок выборка равномерна, а при ошибках проблемный символ получает
   больший вес;
5. генератор не вырождается в один символ, когда доступно несколько;
6. неверный ввод увеличивает статистику ожидаемого символа и `Backspace` её не
   уменьшает.

Ручная проверка: подключить K:04, выбрать `Symbols`, увидеть символы основных
и дополнительных слоёв, намеренно ошибиться на одном знаке, завершить
упражнение и убедиться, что в следующем этот знак попадается заметно чаще.
